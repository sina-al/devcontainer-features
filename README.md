# sina-al/devcontainer-features

A public, canonical collection of self-authored [dev container features](https://containers.dev/features).
Owning the features I depend on removes the trust gap with third-party ones: I control the
install code, the versions, the tests, and the published artifacts. Features publish to GHCR
as `ghcr.io/sina-al/devcontainer-features/<feature>:<version>` and are referenced by major
version (`:1`).

The repo layout and release workflow are derived from the official
[`devcontainers/feature-starter`](https://github.com/devcontainers/feature-starter) template.
See `AGENTS.md` for the conventions baked into every feature, and `HANDOFF.md` for the
original stand-up plan.

## Features

| Feature | Description |
| --- | --- |
| [`fireconnect`](src/fireconnect/README.md) | Installs the [FireConnect](https://github.com/fw-ai/fireconnect) CLI, which routes coding agents (OpenCode, Claude Code, Codex, and others) through Fireworks AI models. |
| [`devcontainers-cli`](src/devcontainers-cli/README.md) | Installs the official Dev Container CLI (`devcontainer`) via its self-contained installer. |
| [`uv`](src/uv/README.md) | Installs [uv](https://docs.astral.sh/uv/) and `uvx`, Astral's extremely fast Python package and project manager, via the official standalone installer. |

## Usage

Reference a feature by its published GHCR address with a major-version tag. Options go under
the reference in a `features` map:

```jsonc
"features": {
  "ghcr.io/sina-al/devcontainer-features/fireconnect:1": {
    "version": "latest",
    "login": false
  },
  "ghcr.io/sina-al/devcontainer-features/devcontainers-cli:1": {
    "version": "latest"
  }
}
```

`version` pins the tool the feature installs (`latest` or a specific tag/SHA); the `:1`
suffix pins the feature itself to a major version. See each feature's README for its options.

## Work on this repo

This repo has its own devcontainer (`.devcontainer/`) for authoring and testing features. It
provides Docker-in-Docker and the `devcontainer` CLI, which `devcontainer features test`
requires. Run it with [DevPod](https://devpod.sh):

```sh
devpod up .                   # local
devpod up . --provider gcloud # remote on GCP
devpod ssh .
# inside:
devcontainer features test --features devcontainers-cli .
devcontainer features test --features fireconnect --skip-autogenerated .
devcontainer features test --global-scenarios-only .
```

> Bootstrap note: until `devcontainers-cli` is published from this repo, the devcontainer
> installs the `devcontainer` CLI directly in the `Dockerfile` via the official install
> script. Switch to the self-published `:1` feature in `devcontainer.json` once it exists.

## Publishing

Releases are published manually via the `release.yaml` workflow (Actions → "Release dev
container features & Generate Documentation" → Run workflow, from `main`). It uses
[`devcontainers/action`](https://github.com/devcontainers/action) to publish each feature in
`src/` to GHCR and regenerate per-feature `README.md` documentation via a pull request.

After the first release, flip each GHCR package's visibility to **public** at its package
settings page (packages default to private).
